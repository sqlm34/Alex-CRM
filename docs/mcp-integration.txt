BOOKING / CONFIRMATION FLOW
1. Read current policy, collect appliance, issue and diagnosis/requestedService.
2. Ask ZIP, collect complete street address; checkServiceArea and getAvailableSlots.
3. Collect name, phone, email, choose a returned date/window in Indianapolis time.
4. Read back exact details and obtain explicit agreement. Call createBooking with
   confirmed:true and a UUID idempotencyKey. No confirmationToken is needed yet.
5. It returns confirmed:false, confirmationRequired:true and a secure URL. The
   customer opens it, authenticates with the SAME identity, reviews the values and
   presses Confirm request after Turnstile. Approval expires after ten minutes.
6. Retry createBooking with IDENTICAL data and key. The transaction rechecks policy,
   risk, lead time and availability, inserts the existing CRM job and ownership
   receipt, and consumes approval. Only confirmed:true means it was booked.
7. On slot_unavailable obtain fresh windows and new customer approval/key. On a
   timeout or uncertain result retry the SAME key; never fabricate a second order.
8. Cancellation follows the same prepare -> browser approval -> retry sequence.

The confirmation page intentionally says approval is not yet a booking. It does
not store access tokens in URLs, browser storage, logs or assistant messages.
Only PKCE/state/temporary intent state is kept in sessionStorage until sign-in.
A non-secret device identifier is retained locally for the existing risk checks.
The page is scrollable on small phones so long descriptions are never clipped.
MCP jobs have booking_source=website, booking_source_detail=mcp_assistant and use
existing owner push/email and configured customer notification processing.
The existing delivery functions remain best effort; client connectors must not
interpret a notification timeout as permission to create another appointment.

OAUTH SETUP - REQUIRED BEFORE ENABLING WRITES
No customer OAuth authority already configured for this feature was assumed.
Provision/configure a customer identity provider separately from CRM owner login.
It must provide HTTPS discovery, authorization code+PKCE, JWT access tokens and
client registration compatible with the chosen assistant (pre-registration is OK).
Register the MCP resource audience exactly as MCP_RESOURCE_URL, including /mcp.
Tokens must contain iss, sub, exp, iat and space-separated scope. Supported signing
algorithms: RS256 and ES256. The issuer must assert phone_number in E.164 and
phone_number_verified=true only after its own verification. Clients may not set
these claims themselves. An ID token is not a substitute for an access token.
JWKS/auth/token endpoints are restricted to the configured issuer's HTTPS origin.

Register a separate PUBLIC PKCE browser client for the confirmation page:
- redirect URI: <MCP origin>/mcp/confirm (exact match, no wildcards)
- token endpoint authentication: none, PKCE S256 mandatory
- CORS: allow that origin at the provider token endpoint
- scopes: openid phone booking:create booking:cancel
- access-token audience: the same MCP resource
- use the same stable issuer/subject as the assistant connector client
Register ChatGPT/Claude redirect URIs shown by their CURRENT setup screens exactly.
Do not guess callbacks, share refresh tokens, or put client secrets in repository
JSON. If the provider requires confidential assistant clients, enter their secrets
only in the client's secure connection setup, not this public browser client.

VARIABLES / SECRETS
See config/mcp/worker-vars.example.json; all placeholder values require replacement.
MCP_ENABLED=false disables all MCP routes (404), including metadata and confirmation.
MCP_WRITES_ENABLED=false blocks creation, approval and cancellation, retaining reads.
MCP_RESOURCE_URL is pinned, not derived from attacker-supplied headers.
MCP_CONFIG optionally packs only allowlisted non-secret MCP connection settings
into one JSON binding to fit Workers Free limits. It cannot change enable/write
flags, Turnstile secrets or unrelated CRM settings. Invalid JSON fails closed.
MCP_OAUTH_ISSUER, MCP_OAUTH_JWKS_URL configure the trusted customer token issuer.
MCP_CONFIRM_CLIENT_ID / AUTH_URL / TOKEN_URL configure the browser PKCE client.
MCP_CONFIRM_CONNECTION optionally selects SMS for interactive login. Silent SSO
does not force that connection; validated login/consent errors allow one fallback.
MCP_ALLOWED_ORIGINS is an explicit comma-separated allowlist; no wildcard. Requests
without Origin are accepted for authenticated server-to-server MCP clients.
Reuse existing DATABASE_URL, TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, geocoding
secret, boundary fingerprint and notification secrets ONLY in the Worker secrets.
The Turnstile widget must allow the confirmation hostname. Never bypass Turnstile
or forge a success token to make assistant writes work.

DATA / SECURITY
Migration: migrations/2026-10-25_mcp_booking.sql. Apply only after existing booking,
receptionist, optional-coordinate and customer notification migrations are present.
It adds support tables and extends the existing job-source constraint. It does not
copy orders, reset policies or change past jobs. Review any extra production source
values before applying the constraint extension.
Operations retain idempotency tombstones when a job is deleted. Keys cannot silently
create replacements. Owner identity is a hash of trusted issuer plus subject.
Audit records contain tool, identity hash, outcome and timestamp, not tool arguments.
Intent payloads contain customer data, expire in ten minutes and are purged by the
existing five-minute scheduler when MCP is enabled. Approvals expire likewise.
Rate counters: 60 requests/minute/IP hash and 60/minute/identity; fail closed on DB
failure. Maximum request body: 32 KiB. Unknown origins and invalid hosts are rejected.
Audit retention: 90 days; rate-counter retention: one day. Ownership/idempotency
records persist to prevent replays. Rollback disables cleanup; purge expired intents
manually if leaving MCP off for an extended period. Never delete operation receipts
as routine cleanup. Production privacy policy must describe this retention.
